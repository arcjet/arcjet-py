## Correlation precedence

Highest first: **explicit argument → `RunnableConfig` → ambient `ContextVar` → none.**

The engine (`_resolve_correlation_id`) implements the last two tiers. The adapter folds the first two in before calling: it resolves the `RunnableConfig` value and passes `correlation_id=explicit if explicit is not None else from_config` to the engine, which then falls back to ambient.

**`RunnableConfig` key:** read `config["configurable"]["arcjet_correlation_id"]`, then `config["metadata"]["arcjet_correlation_id"]`. Both dicts propagate to child runnables in LangChain, and applications legitimately use either — `configurable` for values code reads, `metadata` for values tracing carries. Accept both; prefer `configurable`.

**Deliberately not used:** LangChain's own `run_id`. `../../../../arcjet/docs/adrs/2026-08-06-eve-guard-surfaces.md` requires correlation to be derived from the user-facing session so a subagent's decisions land on the Sequence a human would query. A per-run id generated by the framework creates a Sequence nobody looks for. Document this in the module docstring so it is not "fixed" later.

Validate a value read from config with the same rule Phase 1 applies (≤256 bytes printable ASCII). A config-supplied value that fails validation must **not** raise into the tool call — log on the `arcjet` logger and fall through to the ambient tier. Rationale: an explicit argument is the programmer's own mistake and should raise; a `RunnableConfig` value may have arrived from a caller several layers away, and blowing up a tool call over a malformed trace id would be worse than losing the join. Export a small internal validator from `_context.py` for this rather than duplicating the rule.

**Step 1 — narrow the typed errors onto the core pair.** Keep both constructors and both messages byte-identical so existing assertions hold; only the bases change:

```python
class ArcjetToolDeniedError(ArcjetDeniedError, ToolException):
    """Raised when Arcjet policy denies a LangChain tool call."""


class ArcjetToolUnavailableError(ArcjetUnavailableError, ToolException):
    """Raised when a required Arcjet policy cannot be evaluated."""
```

Both base pairs already define the `__init__` these need (`_errors.py`, Phase 3 Task 1) with identical signatures and messages, so the bodies can go. MRO resolves cleanly: `ArcjetToolDeniedError → ArcjetDeniedError → ToolException → Exception`. Existing `except ToolException` handlers in LangChain still catch them, and new `except ArcjetDeniedError` handlers in framework-free code catch them too.

Delete `_check_decision()` (line 74) — the engine's `_classify_decision` replaces it.

**Step 2 — add correlation resolution.** A module-level helper reading both config locations:

```python
_CORRELATION_KEY = "arcjet_correlation_id"


def _correlation_from_config(config: RunnableConfig) -> str | None:
    """Read a correlation ID out of a RunnableConfig, or return ``None``.

    Checks ``configurable`` before ``metadata``: both propagate to child
    runnables, and applications legitimately use either.

    A malformed value is dropped with a log line rather than raised. An
    explicit argument is the programmer's own, and should fail loudly; a
    config value may have arrived from several layers away, and failing a tool
    call over a bad trace id trades a lost join for an outage.
    """
```

**Step 3 — rewire `invoke` and `ainvoke`.** Each becomes: resolve the config correlation ID, then hand everything to the engine with a `prepare` closure and the LangChain error factories. The `try` / `except ArcjetToolDeniedError` around the whole thing stays, because `handle_tool_error` delegation must still convert a denial into a `ToolMessage`:

```python
    def invoke(
        self, input: Any, config: RunnableConfig | None = None, **kwargs: Any
    ) -> Any:
        if not isinstance(self._guard, ArcjetGuardSync):
            raise TypeError(
                "A synchronous LangChain invocation requires ArcjetGuardSync"
            )
        resolved_config = config if config is not None else cast(RunnableConfig, {})

        def prepare() -> ResolvedInputs:
            arguments = _arguments(self._tool, input)
            return ResolvedInputs(
                actor=self._resolve_actor(resolved_config),
                inputs=self._resolve_inputs(arguments, resolved_config),
            )

        try:
            return run_checkpoint_sync(
                lambda: self._tool.invoke(input, config=config, **kwargs),
                action=self._action,
                guard=self._guard,
                prepare=prepare,
                rules=self._rules,
                correlation_id=_correlation_from_config(resolved_config),
                on_guard_error=self._on_guard_error,
                denied_error=ArcjetToolDeniedError,
                unavailable_error=lambda action, cause: ArcjetToolUnavailableError(
                    action, cause=cause
                ),
            )
        except ArcjetToolDeniedError as exc:
            return _handle_tool_exception(self, exc, input)
```

Three behavior changes to be deliberate about, because they are what makes existing tests keep passing:

1. **The wrapped tool now runs inside the engine**, so a tool that raises produces an `outcome="error"` capture and the exception propagates unchanged. Previously the tool ran outside any try. Nothing existing asserts otherwise.
2. **`_handle_tool_exception` must still see only `ArcjetToolDeniedError`.** The engine re-raises the callable's own exceptions untouched, so a `ToolException` from the *wrapped tool* keeps reaching LangChain's own handling rather than Arcjet's — same as today.
3. **`on_guard_error="allow"` with a raising `guard()` still executes the tool.** The engine's fail-open branch handles this; the old code did it by falling out of `except Exception` without re-raising.
4. **`__cause__` on the failed-open path becomes `None`.** Today the failed-open path double-wraps: `_check_decision` raises `ArcjetToolUnavailableError(action)` (`langchain.py:80`), the broad `except Exception as exc` at `:165` catches its *own* exception, and re-raises a second one as `ArcjetToolUnavailableError(action, cause=exc) from exc` — so `__cause__` is a redundant copy of itself. Under the engine, `_classify_decision` returns `unavailable_error(action, None)` directly and `__cause__` is `None`, which is more truthful: nothing caused it, the policy simply did not evaluate. The `guard()`-raised path still sets a real `__cause__`. No existing test asserts on `__cause__` (the only exception assertion in the whole file is `pytest.raises(ArcjetToolDeniedError)` at `test_langchain.py:120`), so `langchain-helper.AC1.7` is not at risk — but do not "restore" the old double-wrap on seeing the difference.

Do not pass `actor` / `inputs` alongside `prepare` — `prepare` supersedes them.

**Step 4 — no mutation.** `_arguments()` already builds a fresh mapping; leave it. Do not add a `dict(...)` copy of `inputs` anywhere: Phase 3 asserts the mapping reaches `guard()` by identity.
